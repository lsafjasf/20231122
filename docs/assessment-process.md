# 评估与复核流程

## 输入归一化

所有时间以“恢复后重放起点 0:00”为原点，统一归一化为毫秒。

| 旧版字段 | 新版字段 | 归一化规则 |
|---|---|---|
| `version <= 1` | `format_version >= 2` | 旧版标记 `migrated=true`，自动结论加“需关注” |
| `t` / `time` 数字 | `timestamp_ms` | 旧版数字按秒，新版数字按毫秒 |
| `HH:MM:SS.mmm` | 同上 | 统一转换为毫秒 |
| `duration` 数字 | `duration_ms` | 旧版数字按秒 |
| `track` 数字 | `track_id` | 解析到 `tracks[].index` 或 `tracks[].id` |
| `frame_index` | `frame` | 转为无符号整数 |
| `lost=true` | `kind=packet_loss` | 统一为丢包事件 |
| `plc_params` | `processing[].parameters` | 与事件级参数合并，事件值优先 |
| `sample_rate/channels` | `tracks[].sample_rate/channels` | 无轨道表时建立主轨道 |

无法解析时间点的条目会进入清单警告，不会伪造时间。没有事件时自动结论为“需关注”，不会宣称通过。

## 解码与波形

GStreamer 管线为：

```text
filesrc -> decodebin -> audioconvert -> audioresample
        -> audio/x-raw,F32LE,mono,48kHz -> appsink
```

扩展名不参与格式选择。证据记录文件头、内容提示和实际协商 caps。输出波形按 10 ms 分桶保留 min/max/RMS，并写入 `output-waveform.wav`。

## 自动检查

| 检查 | 通过条件 | 不通过/需关注 |
|---|---|---|
| 解码 | 产出非空音频 | 解码器、插件或码流错误 |
| 未知扩展 | 扩展名在已知列表 | 记录未知扩展，要求人工确认 |
| 格式迁移 | 新版格式 | 旧版迁移，要求人工抽查 |
| 事件 | 至少一个可解析事件 | 无事件，不能自动判定通过 |
| 完整性 | 未截断、非近静音 | 截断、峰值低于 -80 dBFS |
| 事件窗口 | 有波形窗口且无异常 | 越界、零时长、静音、削波、显著幅度跃变 |
| 映射 | 轨道、帧、参数可追溯 | 缺失项逐事件标注 |

自动结论规则：任一失败为“失败”；否则任一需关注为“需关注”；全部通过才是“通过”，但仍要求人工听辨。

## 人工确认

人工项目至少包含：

1. 原始音频副本哈希与记录一致。
2. 完整回放，未发现未记录的断音、爆音或节奏漂移。
3. 时间点、轨道/帧和处理参数已与原始恢复记录交叉核对。
4. 每个事件逐条听辨。
5. 未知扩展名对应流程已确认。

人工状态独立计算：任一“不通过”即不通过；否则任一“需关注”即需关注；仍有“待确认”则保持待确认；全部通过才是通过。

## 证据复核

```bash
alc-review verify --evidence <证据目录>
```

命令读取 `evidence-index.json`，逐个重算 SHA-256，并检查 `report.md` 是否仍同时具备“自动结论”和“人工确认”两节。结果写入 `verification.json`。

复核原则：

- 保留原始输入副本，不在原文件上做归一化。
- 自动结论文件只由自动流程写入。
- 人工确认文件只由复核人操作写入。
- 报告更新不删除历史证据；需要重跑时使用新目录。
- 哈希不一致时停止采信该证据包，重新采集并比对。

## 已知边界

- 48 kHz 单声道是分析副本，不替代原始多轨/多声道证据。
- 10 ms 分桶指标适合筛查异常，不等同于听觉质量评分。
- 清单参数缺失不会被推断为默认值。
- `ALC_MAX_SECONDS` 可提高分析上限；默认 1 小时，超限会截断并标记“需关注”。
